# P&L Report Wildberries — Google Sheets + Apps Script

Скрипты — в папке [`apps-script/`](apps-script). Файлы пронумерованы **в том порядке, в котором их нужно
создавать в проекте Apps Script**. Лист INFO в таблице (меню «Отчёты МП» → «Листы» → «Обновить INFO») — тот же README.

## 1. Листы таблицы

| Лист | Роль |
|---|---|
| `INFO` | README проекта |
| `LOG` | журнал загрузок (был `Load_log`) |
| `DATA_CHECK` | контроль полноты `DATA_WB` (был `Data_check`) |
| `SKU_WB` / `SKU_OZ` | товары Wildberries / Ozon (были `Report_sku_wb` / `Report_sku_oz`) |
| `COGS` | себестоимость (заполняет пользователь) |
| `REPORT_OZ` | данные Ozon, cash flow (был `Report_finans_oz_1`) |
| `DATA_WB` | данные Wildberries (был `Data_wb`) |
| `ПАРАМЕТРЫ` | **вкладка 1** Web App |
| `P&L ОТЧЕТ` | **вкладка 2** (был `Calculation`) |
| `ТОВАРЫ` | **вкладка 3** (был `Calculation_sku`) |
| `UNIT` | **вкладка 4** (был `Unit`) |
| `СПРАВКА` | **вкладка 5** |

Все имена — в одном месте: [`00_Config.gs`](apps-script/00_Config.gs). Переименовали лист — поменяйте одну строку (названия вкладок Web App
подставляются из имён листов). Лист эквайринга WB (`REPORT_WB`) в вашем списке не значился — если он есть под другим именем, поправьте `SHEET_REPORT_WB`.
Порядок листов — `SHEET_ORDER`; меню «Листы» → «Расставить листы по порядку».

## 2. Как загрузить скрипты в Apps Script

1. **Удалите старые файлы проекта:** `Auth`, `Calculation_sku`, `Charts`, `Code`, `Data_check`, `Get_sku_oz`, `Get_sku_wb`, `Index`,
   `Report_finans_oz_1`, `Report_finans_wb_2`, `Unit`. (Если оставить, будут конфликты имён.)
2. **Создайте файлы-скрипты** (Файлы → «+» → Скрипт) в этом порядке, имя — без расширения, содержимое — из одноимённого `.gs`:

| № | Файл | Что внутри |
|---|---|---|
| 1 | `00_Config` | имена листов, раскладка листов, настройки (загружается первым) |
| 2 | `01_Utils` | даты, числа, нумерация строк (иерархия), выпадающие списки, кэш |
| 3 | `02_Formulas_RU` | формулы на русском |
| 4 | `03_Auth` | API-ключи |
| 5 | `04_Menu` | меню «Отчёты МП», `doGet` |
| 6 | `05_Wb_Load` | загрузка WB: точки входа, очередь, API, журнал `LOG` |
| 7 | `06_Wb_Sheet` | запись в `DATA_WB`, нормализация, очистка |
| 8 | `07_Wb_Reports` | `SKU_WB`, эквайринг |
| 9 | `08_Oz_Reports` | `REPORT_OZ`, `SKU_OZ` |
| 10 | `09_Data_Check` | контроль данных → `DATA_CHECK` |
| 11 | `10_Setup` | проверка/создание листов, их порядок |
| 12 | `11_Info` | лист `INFO` |
| 13 | `12_Web_App` | общие вызовы Web App (инициализация, период, права) |
| 14 | `13_Web_Params` | вкладка 1 — `ПАРАМЕТРЫ` |
| 15 | `14_Web_Pnl` | вкладка 2 — `P&L ОТЧЕТ` + ряды для графиков |
| 16 | `15_Web_Goods` | вкладка 3 — `ТОВАРЫ` |
| 17 | `16_Web_Unit` | вкладка 4 — `UNIT` |
| 18 | `17_Web_Ref` | вкладка 5 — `СПРАВКА` |

3. **Создайте HTML-файлы** (Файлы → «+» → HTML), имя — без расширения: `Index`, `Css`, `Js_core`, `Js_hier`, `Js_chart`, `Js_params`,
   `Js_pnl`, `Js_goods`, `Js_unit`, `Js_ref`, `Js_boot`. Страница собирается из них через `<?!= include('…') ?>` в `Index`.
4. Сохраните, обновите таблицу. Меню **«Отчёты МП» → «Листы» → «Проверить структуру листов»** покажет, каких листов не хватает и что не так в раскладке.
5. **Развернуть → Управление развёртываниями → Изменить → Новая версия** (иначе Web App покажет старую страницу).

Порядок файлов не критичен для работы (проверено: проект загружается и в обратном порядке), но так проще сопровождать.
**Триггеры не нужно создавать заново:** имена `dailyUpdate`, `continueLoadQueue`, `OzFin1_monthlyUpdate`, `firstRun`, `loadYesterday` не менялись.

## 3. Вкладки Web App

**Шапка страницы** (над вкладками) у каждой вкладки своя:

| Вкладка | Подзаголовок | Поставщик | Период | Валюта | Сформирован |
|---|---|---|---|---|---|
| ПАРАМЕТРЫ, P&L ОТЧЕТ, ТОВАРЫ | Отчёт о прибылях и убытках | `P&L ОТЧЕТ!A3` | `E2`/`E4` — `G2`/`G4` листа P&L ОТЧЕТ | `P&L ОТЧЕТ!B5` | — |
| UNIT | то же | то же | то же | `P&L ОТЧЕТ!B5` | `UNIT!C4` |
| СПРАВКА | **Сверка расчетов Wildberries** | `СПРАВКА!B4` | `СПРАВКА!D4` — `F4` | `СПРАВКА!H4` (если пусто — `P&L ОТЧЕТ!B5`) | `СПРАВКА!D2` |

Строка периода выглядит так: `Период отчёта 01.09.2026 — 29.09.2026 · в BYN · Сформирован: 30.09.2026`. Пустая валюта или дата — соответствующая часть не показывается.
Эти же значения попадают в шапку выгрузки PDF / Excel / печати. Пояснительные тексты под таблицами убраны.

Название вкладки = имя листа. Каждая вкладка при открытии, каждые ~40 с, при возврате на страницу и по кнопке **«Обновить данные»** перечитывает свой лист
«как есть» (значения ваших формул); если в листе ничего не менялось, таблица не перерисовывается. Фильтр периода (E2/G2 на листах `P&L ОТЧЕТ`, `ТОВАРЫ`, `UNIT`)
действует на вкладки 2–4; на вкладках `ПАРАМЕТРЫ` и `СПРАВКА` остаётся только «Обновить данные».

### 1. ПАРАМЕТРЫ
Заголовки `A6:C6`: `№ | Параметры | Выбор и ввод данных`, параметры — с 7-й строки (например `C8` Беларусь, `C9` ОСНО, `C10` Да, `C11` 20%).
- ячейка `C` с выпадающим списком (проверка данных «значение из списка/диапазона») → **выпадающий список** с теми же вариантами;
- ячейка с формулой → только чтение; прочая ячейка с подписью в `B` → поле ввода; строка с подписью без значения → заголовок группы.
- Выбор записывается в ячейку; значения, изменённые в таблице, подтягиваются в приложение. Варианты читаются из правила ячейки при каждом обновлении,
  поэтому зависимые списки работают. Значение вне списка сервер не запишет.

### 2. P&L ОТЧЕТ
Шапка — строки 1–4, заголовки — строка 6 (`№ | Наименование показателя | Сумма | Доля, % | периоды E…`), строка 7 — «Параметры»
(у месяца — дата конца месяца, у дня — день недели), показатели — ниже. Колонка периода с пустым заголовком или «-» не показывается.
- **Сворачивание следует нумерации колонки A:** `1`, `1.1`, `2`, `2.1`, `2.1.1` … Родитель строки `2.1.1` — `2.1` (если нет — `2`). Строка с подстроками
  сворачивается кликом (стрелка ▾), прячутся **все** потомки; вложенные свёрнутые строки остаются свёрнутыми при разворачивании родителя;
  кнопка в шапке «№» сворачивает/разворачивает всё. Состояние сохраняется при обновлении данных.
  В колонке «№» **слева — крупная стрелка** (у строк без подстрок — пустое место такой же ширины), **справа — номер**: первые цифры всех номеров стоят на одной вертикали.
- Совет: формат колонки A — «Обычный текст», иначе таблица превратит `1.10` в `1.1`, а `1.1` может показать как дату (скрипт возвращает `1.1` из даты/числа, но `1.10` восстановить не может).
- ✎ у названия — строка ручного ввода (в колонках периодов нет формул, «Сумма» заполнена).

**Графики при наведении (линейные).** Оранжевая «Сумма» — у строк, для которых график есть.
1. Название строки подходит под правило из `PNL_SERIES_RULES` (`00_Config.gs`: доходы, выручка, возвраты, к перечислению, СПП, расходы МП, комиссия, логистика, %, хранение, штрафы) —
   **дневной ряд за весь период из `DATA_WB`** + среднее за 7 дней; наведение на ячейку дня/месяца подсвечивает его на графике.
2. Иначе — по **дневным колонкам самого листа** (как на `UNIT`): у **итоговых строк** (с подстроками) от 2 значений, у остальных — от 14 (`CHART_MIN_POINTS_*`).
   Так графики есть и у итогов, в которые входят строки ручного ввода (прямые расходы, валовая прибыль, OPEX).
3. Остальные строки — без графика.
Если названия строк в вашем листе отличаются, поправьте/добавьте правила в `PNL_SERIES_RULES`.

### 3. ТОВАРЫ
Колонки читаются по заголовкам строки 6: `№ | Артикул WB | Артикул | Категория товара | Выручка | Логистика | Логистика % | Расходы | Себестоимость | ВП | Маржа, % | Доля, % | XYZ | ABC`
(порядок и состав можно менять; колонка с пустым заголовком или «-» не показывается). Формулы — ваши (себестоимость — из `COGS`).
Поиск, фильтр A/B/C, сортировка, подгрузка по 50 строк. График при наведении — продажи артикула по неделям.

### 4. UNIT
Артикул — `C5` (выпадающий список); выбор в приложении записывается в `C5`, лист пересчитывается. Нумерация строк в колонке A, как в `P&L ОТЧЕТ`
(теперь любой глубины: `1`, `1.1`, `1.2.1`). Колонки без даты в строке 6 скрыты. График — по дневным колонкам.

### 5. СПРАВКА
- `B2` — **выпадающий список «номер отчёта»** (подпись — `A2`). Выбор в приложении записывается в `B2`, лист пересчитывается (ваши формулы берут номер отчёта из `B2`),
  таблица обновляется; если `B2` меняют в таблице — приложение подхватывает.
- Строка 6: `№ | Страна: | Итого | Армения | Беларусь | Казахстан | Киргизия | Россия …` — **страны можно добавлять справа**, новые колонки появятся сами.
- Данные — с 7-й строки; нумерация колонки A задаёт сворачивание, как в `P&L ОТЧЕТ`. Значения показываются **как в таблице** (формат ячеек: %, разряды, единицы).
- Колонка «Итого» выровнена по центру (заголовок и значения). Шапка страницы — из ячеек `B4`, `D2`, `D4`, `F4`, `H4` (см. таблицу выше).

## 4. Меню «Отчёты МП»
- **Wildberries** / **Ozon** — ключи API, первый запуск (3 месяца), автозагрузка (WB — ежедневно в 6:00 МСК, Ozon — 10-го числа).
- **Открыть отчёт**.
- **Листы** — проверить структуру листов · создать недостающие листы (только отсутствующие, с заготовкой шапки) · расставить листы по порядку ·
  создать шапку `ТОВАРЫ` · формулы активного листа → на русском · обновить `INFO`.
- **Дополнительно** — обновить WB за последние дни, загрузить за период, очистить старше 3 месяцев, `SKU_WB`, эквайринг, `SKU_OZ`, контроль данных.

## 5. Что изменено «параллельно»
- **Отправка писем (`MailApp.sendEmail`) удалена** вместе с настройкой адреса: контроль данных больше не шлёт письма, результат — лист `DATA_CHECK` и плашка статуса в шапке.
  Скрипту больше не нужно разрешение «Отправлять письма от вашего имени».
- Все имена листов и раскладка — в `00_Config.gs`; вкладки Web App строятся из конфигурации.
- `Листы → Проверить структуру листов` / `Создать недостающие листы` / `Расставить листы по порядку`.
- Запись из Web App (параметры, артикул `UNIT`, номер отчёта, период) — флаг `WEB_REQUIRE_EDITOR` (по умолчанию выключен): при `true` писать могут только
  редакторы таблицы (работает, если Web App развёрнут «от имени пользователя, открывшего приложение»).
- Даты фильтра периода пишутся настоящими датами (раньше — строкой, зависящей от локали таблицы).
- В строке «Параметры» даты концов месяцев больше не превращаются в «31,08».
- Тихое обновление не перерисовывает поле, которое сейчас редактируется (параметры, списки).
- Убрана генерация листа `Calculation` из кода (`initCalculationSheet`, `calcFormula`, `forceRebuild…`): лист ведётся вручную по вашей структуре
  (раньше эти функции могли пересоздать лист со старой раскладкой). Остались: формулы на русском, перевод листа.

## 6. Допущения — проверьте
- За основу взята ветка `claude/awesome-davinci-b6je5n` (в запросе — `Cloude/awecome-davinci-b5je5n`).
- `P&L ОТЧЕТ`: колонки `№ | Наименование | Сумма | Доля | периоды` и строки 6–7 — как раньше; нумерация вложенности — только по колонке A. Валюта шапки — `B5`.
- Подзаголовок «Сверка расчетов Wildberries» заменяет «Отчёт о прибылях и убытках» **только на вкладке СПРАВКА**; поставщик (`B4`) выводится как «Продавец — …», если в ячейке нет слова «Продавец»/«Поставщик».
- Валюта на СПРАВКЕ: сначала `H4`, если пусто — `P&L ОТЧЕТ!B5` (в запросе указаны обе ячейки).
- Фраза «Строки сворачиваются по нумерации … подсветится» стояла под таблицей вкладки **P&L ОТЧЕТ** (под ТОВАРЫ текстов нет) — убрана оттуда; осталась пометка про ✎.
- `СПРАВКА`: заголовки строки 6 читаются как `№`, подпись строк (`Страна:`), далее `Итого` и страны; при другой раскладке скажите — поправлю.
- Правила `PNL_SERIES_RULES` написаны по прежним названиям строк (`Чистая выручка (Net Sales)`, `Возвраты`, `К перечислению`, …).
- «Возвраты»/«Возврат»: формулы ищут тип операции из колонки Z `DATA_WB`; `DATA_CHECK` покажет реальные значения и предупредит, если названия расходятся.

## 7. Как проверено
Серверный код и страница прогонялись на модели Google Sheets (ячейки, формулы, display-значения, проверка данных): параметры, иерархия, ряды, ТОВАРЫ, UNIT, СПРАВКА, загрузчик
с очередью и дозагрузкой, права записи; страница — в браузере (Chromium) поверх реального серверного кода: вкладки, выпадающие списки в обе стороны, сворачивание, графики, период.
В реальной таблице и в среде Apps Script проверить это здесь невозможно — после загрузки пройдите пункт 2.4.
