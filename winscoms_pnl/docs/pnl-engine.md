# Движок управленческого P&L (Stage 7)

Принятые решения: режимы **УСН «доходы» 6%** и **ОСНО (налог на прибыль 20%, НДС отдельно)**; выручка = `retailPriceWithDisc`;
себестоимость — через Excel-шаблон; ручные записи для OPEX, внешней рекламы, налогов и корректировок. Где данных нет — логика по описанию
(правила ниже); ничего не ждёт новых выгрузок.

## Слои
```
financial_entries ──┐
manual_entries    ──┼─▶ services/pnl.py (SQL-агрегаты) ─▶ financial/engine.py (чистые функции) ─▶ JSON-отчёт
product_costs     ──┘                                      ▲ pl_template.py (структура P&L — данные)
org_settings (налоги, ставки НДС) ─────────────────────────┘
```
Движок не обращается к БД и не знает про Wildberries. Структура отчёта — список `LineSpec` в `pl_template.py`; новая строка = новая запись
(id, родитель, тип: imported / manual / cogs / formula / ratio / tax / group, знак формулы, режимы, `in_totals`, `optional`, `active`).
Хранение шаблона по организациям (`pl_lines` в БД) не делалось — в v1 один шаблон на всех; движок уже принимает шаблон параметром.

## Строки и формулы (расходы — положительные числа)
| строка | формула |
|---|---|
| Продажи | Σ `sale_revenue` (= `retailPriceWithDisc`) |
| НДС с продаж (ОСНО) | продажи × r/(100+r), r = `vat_sales_rate` |
| **Чистая выручка** | продажи − возвраты − НДС с продаж |
| Затраты маркетплейса | комиссия + эквайринг + логистика (4 вида + вручную) + хранение + приёмка + прочие удержания + штрафы |
| Комиссия | Σ `commission_gross` = `retailPrice × commissionPercent` (с учётом компенсации СПП, см. wb-real-data-findings §2) |
| Себестоимость | штуки проданного × себестоимость единицы на дату продажи + доп. затраты (вручную) |
| **Валовая прибыль** | чистая выручка − затраты маркетплейса − себестоимость |
| Реклама и маркетинг | реклама WB (удержания «WB Продвижение») + внешняя + прочая (вручную) |
| Операционные расходы | зарплаты + ПО + бухгалтерия + прочие (вручную) |
| **Операционная прибыль** | валовая − маркетинг − OPEX |
| **Прибыль до налогов** | операционная + прочие доходы − прочие расходы |
| Налог | УСН: `usn_rate` × **продажи** (не прибыль); ОСНО: `profit_tax_rate` × max(прибыль до налогов, 0) (убыток → 0, без переноса) |
| **Чистая прибыль** | прибыль до налогов − налоги (включая «прочие налоги» вручную) |
| Справочно | маржи, %; НДС к уплате (ОСНО) = НДС с продаж − НДС по услугам WB − НДС по закупкам (вручную); forPay; расчётная выплата WB |

**ОСНО:** суммы услуг WB (комиссия, эквайринг, логистика, хранение, приёмка, реклама) приводятся к «без НДС» делением на `1 + vat_services_rate/100`;
ставка по умолчанию 22% — именно её показывает `vwNds / vw` в реальной выгрузке. Если вы имели в виду НДС 20% — измените ставки в настройках.
Ручные суммы при ОСНО вводятся **без НДС**; себестоимость единицы — без НДС. Допущение: все услуги WB облагаются НДС по одной ставке (часть может быть без НДС).
**УСН:** НДС не выделяется, суммы как в отчёте WB. База налога — продажи по цене продажи (приближение к кассовой базе УСН; точная — по поступлениям — позже).

## «Нет данных» вместо нулей (статусы строки)
`ok` · `incomplete` (посчитано, но есть замечания) · `missing` (нет данных) · `blocked` (нечем считать — значение `null`, справочная оценка в `preliminary`) · `not_applicable`.
- Импортируемая строка: нет импортированных данных за период → `missing`; данные есть, операций нет → честный 0.
- Ручная строка без записей → `missing`. Запись с суммой **0** подтверждает «расходов нет».
- Группы **«Реклама и маркетинг»** и **«Операционные расходы»** требуют подтверждения: хотя бы одна ручная запись (можно 0), иначе операционная и чистая прибыль `blocked`.
- Остальные ручные строки (`optional`: доп. логистика, доп. затраты на товар, прочие доходы/расходы, прочие налоги) отсутствуют «по умолчанию»; это явно написано в `notes`, расчёт не блокируется.
- Себестоимость: если для какого-то проданного товара нет цены — `cogs_goods` и всё ниже (валовая, операционная, чистая) `blocked`, в заметке перечислены nmId.
- В импорте есть строки `inconsistent/unclassified` или неописанные суммы (`unmapped:*`) → импортируемые строки `incomplete`; «Возвраты» и «Штрафы» (нет подтверждённых данных) → `incomplete`, а не тихий 0.
- Суммы `pending`-типов (возмещение издержек, штрафы, `unmapped:*`) в P&L не входят и перечислены в `quality.excluded_pending_amounts`.

## Округление
Листья округляются до копеек **ROUND_HALF_UP**, подтоги и формулы считаются из округлённых листьев, поэтому отчёт «сходится» с собой копейка в копейку.
Проценты — до сотых. В хранилище — NUMERIC(20,6) без округления. Колонка «Итого» считается из суммарных входов, а не суммой колонок
(налог на прибыль с убыточным месяцем ≠ сумме месячных налогов).

## Себестоимость (Excel)
`GET /orgs/{org}/costs/template` — .xlsx с колонками `subjectName, nmId, vendorCode, costPerUnit, validFrom`, заранее заполнен товарами из ваших продаж.
Заполните `costPerUnit` (и при необходимости `validFrom`), загрузите `POST /orgs/{org}/costs/import`. Пустая себестоимость — строка пропускается; одна ошибка —
не загружается ничего (ответ 422 со списком «строка / поле / ошибка»). Новая строка с тем же `nmId` и другой `validFrom` меняет цену с этой даты; повтор той же даты обновляет.
Защита: ≤2 МБ, ≤10 000 строк, проверка формата и размера после распаковки.

## API (все — внутри организации, 404 для чужой)
| метод | путь | роль |
|---|---|---|
| GET/PUT | `/orgs/{org}/settings` | читать — любой участник, менять — админ организации |
| GET | `/orgs/{org}/costs/template`, `/costs` | участник |
| POST | `/orgs/{org}/costs/import` | admin, member |
| GET/POST/PUT/DELETE | `/orgs/{org}/manual-entries` | чтение — все; запись — admin, member |
| GET | `/orgs/{org}/manual-categories` | участник |
| GET | `/orgs/{org}/reports/pnl?date_from&date_to&granularity=total\|month\|day&account_id&currency` | участник |
| GET | `/orgs/{org}/reports/pnl/drilldown?line=…&date_from&date_to` | участник: импортные проводки / ручные записи / продажи с применённой себестоимостью |

Несколько валют в периоде → 409 с просьбой указать `currency` (суммы разных валют не складываются). Отчёт по конкретному аккаунту не включает ручные записи уровня организации.

## Ограничения v1
- Возвраты и штрафы: знак в данных не подтверждён → в расчёт не входят, строки помечены неполными.
- «Возмещение издержек» — ждёт решения (docs/wb-real-data-findings.md §3).
- Нет экспорта CSV/Excel отчёта, нет конфигурируемого шаблона на организацию, нет переноса убытков и кассовой базы УСН.
- Фронтенд отчёта — следующий этап.
