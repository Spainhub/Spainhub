# Принятые решения (согласовано с заказчиком)

| # | Решение |
|---|---|
| Репозиторий | WINSCOMS живёт в отдельной ветке `winscoms/main` без истории и файлов Apps Script. Старый проект не затрагивается. |
| A1 | Валюта определяется полем `currency` каждой записи (на старте `RUB`). Конвертаций нет. |
| A2 | Аккаунты создаёт администратор платформы; публичной регистрации нет. |
| A3 | httpOnly-cookie + серверная сессия в PostgreSQL, Argon2id, CSRF-токен для мутаций. |
| A4 | Очередь — таблица `sync_jobs` + `SELECT … FOR UPDATE SKIP LOCKED`, отдельный процесс-воркер. |
| A5 | Токены шифруются Fernet (MultiFernet для ротации), ключи в env. |
| A6 | Изоляция: обязательный `organization_id` в репозиториях + PostgreSQL RLS. |
| A7 | Интерфейс на русском. |
| A8 | ClickHouse не используется в v1. |
| WB-токен | Персональный; лимит 1 запрос/мин (перепроверить на реальном токене до Stage 5). |
| Выручка | Базовая мера — `retailPriceWithDiscRub`. Точные правила знака/НДС — в `financial-mapping.md` (Stage 7). |
| Налоги | Выбор налоговой политики (УСН «доходы», УСН «доходы−расходы», ОСНО) в настройках организации; НДС показывается отдельной строкой. |
| Реклама | В v1 отдельного рекламного API нет: реклама WB отражается в `deduction`. |
| Роли | Один администратор платформы выдаёт доступы пользователям. Минимальный набор ролей: admin, user (read/write), viewer — уточним на Stage 4. |
| COGS | Ручной ввод и импорт CSV/Excel (по артикулу). Формат файла утвердим на Stage 7. |

## Открытое
- Подтвердить на реальном ответе WB: уникальность `rrdId` внутри аккаунта, точные имена и знаки полей, смысл HTTP 402.
- Уточнить: реклама внутри `deduction` — нужно ли выделять её отдельной строкой P&L по `bonusTypeName`.
- Доступ к VPS и домен — до Stage 10.
