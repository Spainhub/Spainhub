# E-commerce 2.0 — управление проектом (Google Apps Script + Google Sheets)

Веб-приложение из одной страницы: Google Sheets служит базой данных, Apps Script — сервером,
интерфейс — чистый HTML/CSS/JS без зависимостей. Всё, что создано или изменено в интерфейсе,
записывается в таблицу; всё, что есть в таблице, показывается в интерфейсе.

## 1. Структура проекта

| Файл | Назначение |
|---|---|
| `Code.gs` | Сервер: `doGet`/`doPost`, авторизация, создание листов, CRUD, связи, документы, журнал, демо-данные |
| `Index.html` | Каркас страницы: экран входа, вкладки, боковая карточка, модальное окно, подвал |
| `Styles.html` | CSS (подключается через `include('Styles')`) |
| `JavaScript.html` | Клиентская логика: 5 вкладок, формы, диаграмма Ганта, календарь |
| `appsscript.json` | Манифест: V8, часовой пояс, параметры веб-приложения |

## 2. Развёртывание

1. Создайте Google-таблицу (это будет база данных). **Расширения → Apps Script**.
2. Создайте в редакторе файлы с теми же именами: `Code.gs` (скрипт), `Index`, `Styles`, `JavaScript` (HTML).
   Вставьте содержимое файлов из папки. Чтобы увидеть `appsscript.json`: **Настройки проекта → Показывать файл манифеста**,
   затем вставьте его содержимое (часовой пояс поменяйте на свой).
3. Выберите функцию `setup` и нажмите **Выполнить**, подтвердите права доступа к таблице.
   Скрипт создаст листы `Stages`, `Tasks`, `Subtasks`, `Meetings`, `Approvals`, `Links`, `Documents`, `Users`, `Log`, `Settings`
   и запишет пароль `2026` в Script Properties (`APP_PASSWORD`).
   Если листы не создались заранее, они появятся при первом открытии приложения.
4. Необязательно: функция `seedDemo` (или пункт меню таблицы «E-commerce 2.0 → Загрузить демо-данные») наполнит проект примерами.
5. **Развернуть → Новое развёртывание → Тип: Веб-приложение**:
   - *Выполнять от имени*: **Меня** — приложение читает и пишет таблицу с вашими правами, пользователям доступ к самой таблице не нужен;
   - *Доступ*: «Все, у кого есть аккаунт Google» (или «Только пользователи домена» для корпоративного аккаунта).
     Вариант «Все, даже анонимные» (`ANYONE_ANONYMOUS` в манифесте) тоже работает, но тогда защита — только пароль.
6. Откройте выданный URL (`.../exec`), введите имя и пароль `2026`.
7. После правок кода: **Развернуть → Управление развёртываниями → Изменить → Новая версия**, иначе URL отдаёт старую версию.

**Смена пароля.** В Script Properties поменяйте `APP_PASSWORD`, либо меню таблицы «E-commerce 2.0 → Сменить пароль входа»
(второй способ ещё и завершает все активные сессии).

**Безопасность.** Пароль хранится в Script Properties открытым текстом (требование задачи) — это защита от случайных посетителей,
не от целенаправленной атаки. После 5 неверных попыток вход блокируется на 5 минут для всех. Сессия — случайный токен в `CacheService`
(6 часов, продлевается при работе), в браузере лежит в `sessionStorage`. Все строки перед выводом экранируются; ссылки документов
принимаются только `http://` и `https://`.

## 3. Как это работает

- `doGet` отдаёт шаблон `Index` (`HtmlService.createTemplateFromFile`, режим `IFRAME`).
- Клиент вызывает сервер через `google.script.run`. Каждый метод возвращает `{ ok: true, data }` или `{ ok: false, error }`.
  Если сессия недействительна, приходит `code: "AUTH"` и клиент показывает экран входа.
- Публичные методы: `login`, `logout`, `checkSession`, `getAllData`, `getLog`, `createEntity`, `updateEntity`, `deleteEntity`,
  `createLink`, `updateLink`, `deleteLink`, `setParent`, `addDocument`, `updateDocument`, `deleteDocument`, `addUser`, `saveSetting`,
  а также `getInfo`, `getApprovalsRegister`, `setApprovalVoters`, `castVote`, `moveTask`, `getExchangeCards` (см. раздел 7).
- Те же методы доступны как JSON-API: `POST` на URL веб-приложения с телом `{"action":"getAllData","args":["<token>"]}`;
  токен выдаёт `{"action":"login","args":["2026","Имя"]}`. `GET ...?api=ping` — проверка работоспособности.
- Записи под `LockService` — одновременные правки не портят таблицу. Валидация на сервере: обязательные поля, формат дат `ГГГГ-ММ-ДД`
  и времени `ЧЧ:ММ`, прогресс — целое 0–100, допустимые значения справочников, начало ≤ срок, окончание встречи > начало,
  причина при блокировке, правила иерархии связей.
- Каждое создание, изменение (отдельная строка на каждое изменённое поле), удаление, а также связи, документы и вход пишутся в `Log`.

### Вкладки

- **Главная** — блок «Файлы проекта» (лист `Info`), реестр согласований (лист `ApprovalsRegister`), общий прогресс (для этапа и задачи с дочерними элементами считается как среднее по ним), задачи по статусам,
  ближайшие сроки и просрочка, заблокированные, 5 последних событий, редактируемое описание проекта.
- **Обмен** — карточки связей: «Источник» (участник, задача, дата, статус), «Получатель», «Дополнительно» (примечание, комментарий, документы — только если есть),
  в подвале «Что» и «Когда» с состоянием передачи; создание, правка, удаление; фильтр и поиск.
- **Канбан** — колонки «В процессе», «Планируются», «Готово», «Ожидают решения» (просроченные); перетаскивание сохраняет статус и пишется в `Log`.
- **Встречи** — календарь (месяц/неделя). Клик по дню создаёт встречу, клик по встрече открывает карточку.
- **Диаграмма Ганта** — этапы → задачи → подзадачи с прогрессом, ромбы «Требуется решение» для согласований, стрелки передачи результата
  (красная — результат ожидается позже старта получателя), штриховка блокировок, подсветка просрочки, линия «сегодня», плавный масштаб ползунком, фильтр «Блокирующие».
- **Журнал** — история с фильтрами по сущности, датам и ID.

Клик по любому объекту открывает карточку: поля, статус, ползунок прогресса, блокировка (кем и почему), комментарий, смена родителя,
документы (своё название + активная ссылка), связи, история объекта.

## 4. Схема данных

Первая строка каждого листа — заголовки, порядок столбцов не важен (сервер находит столбцы по имени).
Даты, время и метки времени хранятся **текстом** (`2026-11-05`, `10:00`, `2026-10-29 12:00:00`) — Sheets не превращает их в даты.

**Stages / Tasks / Subtasks** (идентификаторы `STG-0001`, `TSK-0001`, `SUB-0001`):
`id, name, description, [task_type — только у задач], assignee, start_date, deadline, status, progress, blocked, blocked_by, block_reason, comment, created_at, updated_at`
`status`: `Not Started | In Progress | Under Review | Done | Blocked`. `progress`: 0–100.

**Meetings** (`MTG-0001`): `id, name, description, assignee (организатор), meeting_date, meeting_time, end_time, participants, location, status, comment, created_at, updated_at`;
`status`: `Planned | Held | Cancelled`.

**Approvals** (`APR-0001`): `id, name, description, initiator, approver, assignee (ответственный за подготовку), deadline, status, blocked, blocked_by, block_reason, comment, created_at, updated_at`;
`status`: `Pending | In Progress | Approved | Rejected`. Если у согласования есть голосующие, статус выводится из голосов (раздел 7).

**Links**: `link_id (LNK-0001), source_id, source_type, target_id, target_type, link_type, note, created_by, created_at`.
`link_type`: `parent` (источник входит в получателя — иерархия, строит дерево Ганта), `blocks` (источник блокирует получателя — сплошная линия на Ганте),
`handoff` (источник передаёт информацию получателю — штрих), `approval` (источник требует согласования; получатель — всегда согласование — точки), `related` (просто связаны). Правила иерархии: задача → этап, подзадача → задача, согласование и встреча → этап/задача/подзадача; у объекта один родитель.

**Documents**: `doc_id (DOC-0001), entity_id, entity_type, doc_name, doc_url, added_by, created_at`.

**Users**: `name, email, role`. Список пополняется автоматически: новое имя из любого поля «человек» или при входе попадает сюда.
Вручную можно добавить email и роль прямо в листе.

**Log**: `timestamp, user, action, entity_type, entity_id, field, old_value, new_value`.
`action`: `create, update, delete, link_add, link_update, link_delete, doc_add, doc_update, doc_delete, vote, login, setting`.

**Settings**: `key, value` (сейчас — `project_description`).

Номера идентификаторов не используются повторно: счётчик хранится в Script Properties (`SEQ_TSK` и т. п.).
Строки в листах можно править руками, но не удаляйте заголовки и не оставляйте пустой ячейку `id`.

## 5. Как расширять

### Добавить поле существующей сущности (например, `priority` для задач)

1. В `Code.gs` добавьте описание в `FIELDS`:
   ```js
   priority: { label: 'Приоритет', type: 'select', enum: 'priority', dflt: 'Medium' },
   ```
   и справочник в `ENUMS`: `priority: [{ value: 'High', label: 'Высокий' }, ...]`.
2. Добавьте ключ `'priority'` в `TYPES.task.fields` на нужное место.
3. Запустите `setup` — столбец добавится в лист `Tasks` справа, данные не пострадают.
4. Всё остальное работает само: форма создания и правки, валидация, запись в `Log` по полю, подпись в журнале строятся из `FIELDS`.
   Типы полей: `text, textarea, date, time, select, user, bool, progress`; `showIf: 'blocked'` показывает поле только при отмеченном флаге.
   Для одного типа можно переопределить подпись или справочник через `TYPES.<тип>.overrides`.

### Добавить новую сущность (например, «Риск»)

1. `TYPES.risk = { sheet: 'Risks', prefix: 'RSK', label: 'Риск', newLabel: 'Новый риск', fields: [...], overrides: {} }` и добавьте `'risk'` в `TYPE_ORDER`.
2. При необходимости укажите допустимых родителей в `PARENT_RULES`.
3. Запустите `setup` — создастся лист `Risks`. Создание, правка, удаление, связи, документы, журнал и пункт меню «Создать» заработают автоматически
   (кнопки меню в `Index.html` — добавьте строку `<button data-act="new" data-type="risk">Риск</button>`).
4. Отображение в специальных вкладках (Гант, календарь, виджеты) задаётся в `JavaScript.html`: функции `ganttRows`, `renderMeetings`, `renderHome`.
   Цвет метки типа — класс `.tag.t-risk` в `Styles.html`.

### Добавить новый лист-справочник

Добавьте его в `AUX` (`имя: [столбцы]`), запустите `setup`, читайте через `readAll_('Имя')`, пишите через `appendObj_` / `updateRow_`
и не забывайте `writeLog_` и `{ write: true }` в `api_`.

## 6. Проверка

Серверная логика и интерфейс проверялись локально на моках сервисов Apps Script (`SpreadsheetApp`, `PropertiesService`, `CacheService`,
`LockService`) и в Chromium через Playwright: вход, создание всех типов, валидация, связи и их правила, документы, удаление с каскадом,
журнал, вкладки и карточки. Для реального развёртывания пройдите шаги из раздела 2 и откройте демо-данные.

## 7. Версия 2: что добавлено

### Новые листы

**Info** — свободный лист «Файлы проекта». Приложение читает диапазон `Info!A1:K50`: в столбце A — название папки, в B — ссылка
(http/https). Подходят и гиперссылки в самой ячейке с названием, и формулы `=HYPERLINK("url";"название")`. Строка из одного названия без ссылки
показывается как заголовок группы. Пустые ячейки пропускаются. Блок на «Главной» подгружается отдельно, есть кнопка «Обновить». В интерфейсе листы и диапазоны не упоминаются.

**ApprovalsRegister** — реестр согласований, одна строка на участника голосования:

| Столбец | Значение |
|---|---|
| `approval_id` | ID из листа `Approvals` (Approval ID) |
| `title` | название согласования (Title) |
| `initiator` | инициатор (Initiator) |
| `created_at` | дата создания согласования, `ГГГГ-ММ-ДД` (Created Date) |
| `deadline` | срок решения (Deadline) |
| `status` | общий статус согласования (Status) |
| `voter` | участник голосования (Voter) |
| `vote` | `Agree` «Согласен» / `Discussed` «Обсуждение» / `No Decision` «Нет решения» / `Disagree` «Не согласен» (Vote) |
| `vote_comment` | необязательный комментарий (Vote Comment) |
| `vote_date` | дата и время голоса (Vote Date) |

### Голосование и статус согласования

- При создании согласования нужно выбрать участников голосования (мультивыбор из `Users`, можно добавить нового) — минимум одного. Каждому создаётся строка с голосом `No Decision`.
- Состав можно менять в карточке; голоса оставшихся сохраняются.
- Голос участник отдаёт в карточке согласования. Голосовать можно только от своего имени: имя входа должно совпадать с участником (сервер это проверяет).
- Итоговый статус: любой `Disagree` — `Rejected`; все `Agree` — `Approved`; никто ещё не решил (все `No Decision`) — `Pending`; иначе — `In Progress`.
  Статус пишется в `Approvals` и копируется в `ApprovalsRegister`; вручную у согласования с голосующими он не меняется.
- Синхронизация в обе стороны: правка названия, срока или инициатора согласования обновляет реестр; если голос исправили прямо в листе, статус пересчитается
  при следующем открытии приложения (или пунктом меню «Пересчитать реестр согласований»), с записью в `Log`.
- Согласования без голосующих (созданные раньше) продолжают работать со статусом, который выставляется вручную.

### Канбан

Колонка вычисляется по данным: `Done` — «Готово»; срок прошёл и не «Готово» — «Ожидают решения»; `Not Started` — «Планируются»; остальные — «В процессе».
Перенос в «В процессе» ставит `In Progress`, в «Планируются» — `Not Started`, в «Готово» — `Done` (прогресс 100). Колонка «Ожидают решения» заполняется автоматически,
перенести в неё нельзя. Просроченную задачу можно перенести в «Готово» или продлить срок в карточке. Возобновлённая задача не остаётся на 100 %.
Любой перенос пишется в `Log` как изменение поля `status`. Карточку можно тащить мышью или за «ручку» пальцем.

### API (добавлено)

| Метод | Назначение |
|---|---|
| `getInfoData(token)` | прочитать `Info!A1:K50` как есть: строки по порядку, у каждой `level` (вложенность) и ячейки с сегментами `{ text, url }` (`getInfo` — псевдоним) |
| `getUsers()` | имена участников для списка на экране входа (без токена; только имена) |
| `getApprovalsRegister(token, approvalId?)` | строки реестра (все или одного согласования) |
| `setApprovalVoters(token, approvalId, voters[])` | изменить состав голосующих |
| `castVote(token, approvalId, voter, vote, comment)` | голос; пересчёт статуса |
| `moveTask(token, id, column)` | перенос карточки Канбана: `progress`, `planned`, `done` |
| `getProjectTable(token)` | плоский список строк иерархии этап → задачи → подзадачи: исполнитель, даты, комментарий, прогресс (для этапа/задачи с дочерними — среднее), полные URL документов, привязанные встречи |
| `getExchangeCards(token, { type })` | данные карточек «Обмена»; `type`: `flow` (по умолчанию), `all` или значение `link_type` |

`createEntity` для согласования принимает дополнительное поле `voters` (массив имён).

## 8. Журнал изменений (v2 к v1)

- Вёрстка на всю ширину окна: убраны ограничения `max-width`, отступы и размеры плавно масштабируются через `clamp()` и CSS-переменные (1280 — 2560+ px), горизонтальной прокрутки страницы нет.
- Единая шкала отступов (4/8/12/16/24/32), типографическая шкала, единые границы и скругления, видимые фокусные кольца, состояния загрузки и пустые состояния на вкладках, подсказки.
- «Главная»: блок «Файлы проекта» (лист `Info`), реестр согласований с раскрывающимися строками.
- Диаграмма Ганта: ортогональные скруглённые коннекторы со стрелками, три стиля (блокирует — сплошная, информирует — штрих, согласование — точки),
  подсказка по наведению на коннектор, подсветка всей цепочки зависимостей; ползунок масштаба с кнопками «Уместить» и «Сбросить» вместо переключателя дни/недели/месяцы;
  фильтр «Блокирующие» (с приглушёнными ближайшими зависимостями); ромбы согласований с легендой и счётчиком голосов.
- Новые типы связей: `blocks`, `approval` (`handoff` теперь называется «Передаёт информацию»).
- Лист `ApprovalsRegister`, голосование, статус согласования из голосов, новый статус `In Progress`, действие журнала `vote`.
- Вкладка «Канбан» с перетаскиванием и сохранением статуса.
- «Обмен»: вместо таблицы — карточки «Источник / Получатель / Дополнительно».
- Серверные функции: `getInfo`, `getApprovalsRegister`, `setApprovalVoters`, `castVote`, `moveTask`, `getExchangeCards`, `syncApprovalsRegister` (меню).
- Манифест `appsscript.json` не менялся: новые листы создаются тем же `setup()`, дополнительные права не нужны.

## 9. Журнал изменений (v3 к v2)

- В интерфейсе нет упоминаний Google Sheets, листов и диапазонов: убраны подсказки, ссылка «Открыть в Google Sheets», тексты пустых состояний переписаны нейтрально. `getInfo` больше не возвращает адрес таблицы.
- Ссылки на документы везде показываются полностью: название (ссылка) и отдельной строкой полный URL, с переносом внутри блока (`overflow-wrap: anywhere`, `min-width: 0`, `max-width: 100%`), `target="_blank"`, `rel="noopener noreferrer"`. Применено в карточке объекта, «Таблице», карточках «Обмена» и блоке «Файлы проекта».
- Новая вкладка «Таблица»: дерево этап → задачи → подзадачи, кнопки свернуть/развернуть (плюс/минус без эмодзи), «Развернуть всё»/«Свернуть всё», поиск (совпадения показываются вместе с родителями), прогресс-бар и %, документы и встречи, пустые состояния. Серверный метод `getProjectTable`.

## 10. Журнал изменений (v4 к v3)

- **Вход.** Имя выбирается из списка участников (столбец `name` справочника `Users`, метод `getUsers`), пароль прежний. Сервер принимает только имя из справочника и сохраняет его в сессии и в `Log`. Пустой справочник — сообщение «Список участников пуст»; для первого запуска добавьте имена в `Users` (или выполните `seedDemo`). Имена, введённые в полях «исполнитель», «инициатор» и т. п., по-прежнему попадают в справочник автоматически.
- **Файлы проекта.** Блок повторяет содержимое `Info!A1:K50` как есть: порядок строк, вложенность (по столбцу и по отступу), обычный текст и гиперссылки на тексте; адрес ссылки не показывается. Описание проекта убрано с «Главной» (серверная часть `saveSetting` осталась).
- **Документы.** Везде показывается только название-ссылка; без названия — «Документ». Журнал больше не записывает адреса (старые записи очищаются при показе).
- **Календарь.** Ниже (≈340 px), с внешними полями и внутренними отступами ячеек; неделя на узких экранах идёт столбцом без горизонтальной прокрутки.
- **Канбан.** На доске этапы, задачи и подзадачи с цветными бейджами типа, фильтр по типу и разбивка в заголовках колонок; перенос работает для всех типов (`moveTask`, запись в `Log`).
- **Гант.**
  - Переключатель «С зависимостями» исправлен: раньше он был заблокирован, пока не включён фильтр «Блокирующие». Теперь он всегда доступен, включает и выключает коннекторы (и приглушённых соседей в режиме «Блокирующие»), состояние хранится в `localStorage` и не сбрасывается при масштабировании и фильтрах.
  - Нумерация `1.`, `1.1`, `1.1.1` считается по всей иерархии (порядок — по дате начала), поэтому фильтры и масштаб её не меняют; меняют её только добавление, удаление и перестановка элементов по датам. Согласования и элементы без этапа/задачи не нумеруются.
  - Ширина колонки «Структура проекта»: перетаскивание границы (и стрелки клавиатуры), кнопка «Развернуть колонку» (по самому длинному названию) / «Сбросить ширину колонки»; ширина хранится в `localStorage`. Названия переносятся на две строки.
